## Changes This Session (2026-10-06)

### Phase B remediation — B5 + B6

- **`pricing-scraper/scraper.py`** — `seed_from_json` now **closes the prior price
  window at ingest**. Before writing a newer observation it sets the earlier open
  row's `valid_to` to the new `valid_from`, so exactly one row per
  `(competitor, product)` keeps `valid_to IS NULL` after any number of snapshots,
  and a superseded row carries a real closed window. The comparison is strict
  (`valid_from < new valid_from`), so a same-date re-run is still idempotent. All
  writes remain in the one transaction.
- **`tests/test_scraper.py`** — 2 new tests (13 → **15**): the
  one-open-row-per-`(competitor, product)` invariant plus a closed prior window
  after a later-dated snapshot; and a run declaring `2026-11-01` after `2026-10-01`
  adds exactly one `pricing_snapshots` row (closes the residual test gap in the
  Phase B review).
- **`import_paths.py`** (new, repo root) — the **one** documented import bootstrap:
  `add_pricing_scraper_to_path()` inserts `pricing-scraper/` onto `sys.path`
  relative to its own `__file__` (never the cwd). No rename, no editable install,
  no per-module one-off.
- **`tests/conftest.py`** — hand-rolled `sys.path` code replaced by the shared
  `import_paths` bootstrap; the suite still resolves `schema` / `scraper` by name
  from any cwd.
- **`.vscode/settings.json`** (local-only, gitignored) —
  `python.analysis.extraPaths = ["pricing-scraper"]` so the editor agrees with
  runtime.
