## Configuration

- `probe_config.yaml` — empty `services`/`timers`, no `ssh` block; `tests.command`
  is the gate used by both the pre-commit hook and CI, narrowed in Phase B to
  `.venv/bin/python -m pytest tests/ -q` (the scaffold-era `[ ! -d tests ]` guard
  is gone). **Phase D appended the notebook gate** to that same one command —
  `jupyter nbconvert --to notebook --execute --stdout
  notebooks/pricing_walkthrough.ipynb > /dev/null` — so a broken walkthrough fails
  the commit and the build exactly like a failing test, with no CI/hook drift.
  CI provisions a repository-root `.venv` so the same command runs there.
- `repo_owners.yaml` (not committed) — asserts the expected GitHub owner for this
  repo so the pre-push hook catches an account-crossing push.
- `secrets_config.yaml` — committed; default forbidden-pattern set.

### Phase C — dashboard + API

- **`pricing-dashboard/app.py`** (new) — one FastAPI app with an `APIRouter`
  exposing `/`, `/comparison`, `/api/pricing` and `/api/pricing/{competitor}`.
  `_is_htmx(request)` gates **every** view route: `HX-Request: true` returns a
  content-only fragment, a direct load returns the full shell. `StaticFiles` is
  mounted at `/static` and the router is included, mirroring the reference
  wiring.
- **`pricing-dashboard/helpers.py`** (new) — plain-dict data access, no ORM.
  Reuses `schema.connect()`; "current price" is a simple `valid_to IS NULL`
  filter. The database path is resolved **per call** from `PRICING_DB_PATH`
  (default: the repo-relative `pricing-scraper/data/market_data.db`), which is
  what makes the dashboard tests hermetic. A missing database degrades to an
  empty state rather than an error.
- **`pricing-dashboard/templates/base.html`** (new) — shell with nav
  (`hx-target="#main"`, `hx-push-url="true"`), the vendored HTMX script and the
  **load-bearing footer disclaimer** (illustrative / not affiliated /
  `data_as_of: 2026-10-01`).
- **`pricing-dashboard/templates/dashboard.html` + `comparison_fragment.html`**
  (new) — the comparison grid and the search view. Sketch corrections applied:
  the search input carries `name="products"` and the route tolerates empty
  input; a legitimately `0.0` price renders as `$0.00` via an explicit
  `is none` check, never as the missing-value dash.
- **`pricing-dashboard/static/htmx.min.js`** (new) — the vendored asset (48 KB,
  MIT). Never a CDN. **`static/style.css`** (new) — hand-written, no build step.
- **`tests/test_dashboard.py`** (new, 21 tests) — parameterized fragment-versus-
  shell tests for both view routes, JSON-versus-HTML separation, the empty-search
  cases, and the zero-price-not-a-dash regression.
- **`tests/conftest.py`** — loads the hyphenated `pricing-dashboard/app.py` by
  file path and adds a `client` fixture that seeds a throwaway DB from the
  committed `sample_data.json` and points the app at it via `PRICING_DB_PATH`.
- **`requirements.txt` / `requirements-dev.txt`** — pinned from `.venv/bin/pip
  freeze` and split so the runtime manifest stays lean (HTMX is vendored, not a
  dependency).

### Phase B remediation — B5 + B6

- **`pricing-scraper/scraper.py`** — `seed_from_json` now **closes the prior price
  window at ingest**. Before writing a newer observation it sets the earlier open
  row's `valid_to` to the new `valid_from`, so exactly one row per
  `(competitor, product)` keeps `valid_to IS NULL` after any number of snapshots,
  and a superseded row carries a real closed window. The comparison is strict
  (`valid_from < new valid_from`), so a same-date re-run is still idempotent. All
  writes remain in the one transaction.
- **`tests/test_scraper.py`** — 2 new tests (13 → **15**): the
  one-open-row-per-`(competitor, product)` invariant plus a closed prior window
  after a later-dated snapshot; and a run declaring `2026-11-01` after `2026-10-01`
  adds exactly one `pricing_snapshots` row (closes the residual test gap in the
  Phase B review).
- **`import_paths.py`** (new, repo root) — the **one** documented import bootstrap:
  `add_pricing_scraper_to_path()` inserts `pricing-scraper/` onto `sys.path`
  relative to its own `__file__` (never the cwd). No rename, no editable install,
  no per-module one-off.
- **`tests/conftest.py`** — hand-rolled `sys.path` code replaced by the shared
  `import_paths` bootstrap; the suite still resolves `schema` / `scraper` by name
  from any cwd.
- **`.vscode/settings.json`** (local-only, gitignored) —
  `python.analysis.extraPaths = ["pricing-scraper"]` so the editor agrees with
  runtime.
